# R15｜200 筆清單分頁與搜尋範圍契約

## 問題與修正
R14 的 `renderList()` 在搜尋全部 `current.conversations` 後，只顯示 `.slice(0,200)`；第 201 筆及以後無法直接從清單選取，使用者可能誤認不存在。R15 保留每頁上限 200，增加上一頁／下一頁與明確頁碼。完整匹配數保留，搜尋涵蓋全部已解析／保留的對話資料；不讀取未匯出的平台資料。

## 操作狀態
- 0、1～200 筆：不顯示分頁控制；201 筆：兩頁，第二頁 1 筆；401 筆：三頁，第三頁 1 筆。
- 分頁只產生當頁最多 200 筆 DOM button，保留每頁選擇與完整 `current` 狀態，不調整 parser、audit 或 snapshot diff schema。
- 搜尋改變、載入新來源、合成示範、清除、匯入失敗：回到第一頁並撤銷過期分頁控制。翻頁後仍可選取、閱讀、按既有敏感 HTML 確認下載。
- 分頁只影響清單呈現，並非會話完整性認證。R14 每段前700訊息閱讀視窗是**不同限制**，匯出仍有 16 MiB guard。

## 安全與驗收
所有輸入皆為原創合成資料，測試涵蓋 0、200、201、401 筆、搜尋跨頁、選取後導覽、換檔、清除與本機無外連。表單互動需鍵盤可用，顯示頁碼以文字呈現，不靠顏色。真人實測由使用者延期；不得將分頁測試當成外部使用者採用。
