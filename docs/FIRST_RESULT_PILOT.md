# R4｜第一次使用成功路徑與真人驗證規格

**狀態：工程可測預覽；真人試用 `NOT_COLLECTED`；外部採用 `NOT_VERIFIED`。**

## 目標與流程

這不是再次增加 AI 功能，而是降低「我不知道要上傳什麼、結果是什麼」的障礙。首次使用建議先開啟 `index.html`，按「試用合成示範」，看看兩份原創假資料的可讀內容、健康指引和差異。此示範來自公開 `examples/sample-newer.json`、`examples/sample-older.json`，不是生成的真人紀錄。

若要檢查自己的帳戶，使用者必須自行透過官方途徑匯出，選擇 ZIP 或 `conversations.json`，工具只在本機瀏覽器讀取。成功標準是**完成有界備份體檢並理解不保證完整**，而不是「所有帳戶資料都已保存」。

## 自願試用的 3 個問題

1. 能否自行完成操作？ `EASY`、`NEEDED_HELP`、`COULD_NOT_FINISH`、`NOT_TESTED`。
2. 結果是否好理解？ `CLEAR`、`NEEDS_EXPLANATION`、`CONFUSING`、`NOT_TESTED`。
3. 下次是否願意使用？ `YES`、`MAYBE`、`NO`、`NOT_TESTED`。

只有 3 個固定選項會寫入本機回饋檔案；工具不自動傳送、記錄或收集。使用者應先閱讀 JSON，若願意再透過 GitHub Issue 送出。不必提供姓名、Email、檔名、匯出 ZIP、聊天對話或螢幕截圖。GitHub Issue 本身可能公開帳號名稱，不是匿名問卷；不願公開時可以完全不送出。

## 研究與回報邊界

- 至少 5 位有意願的獨立一般使用者完成兩組任務：合成示範、自己裝置上的已授權匯出；只收集得到同意的固定選項、總體是否完成、回訪意願。可以只做一組並標註部分完成。
- 使用者自己核對「理解限制」：工具沒有證明所有聊天、圖片、附件或記憶完整；ZIP CRC32 不是原始附件證明。
- 完整流程比較：從取得匯出檔起，到打開結果與理解為止；官方取得時間與網頁操作時間要分開記錄，不用混在單一漂亮數字。
- 不得把團隊自身、合成資料、CI pass、作者操作、GitHub clone/download 當成獨立真人採用。
- 受訪者如不願公開身份，可停止，且不要求提供自己的原始 ZIP、文字或帳號。

## 初步驗收（研究設計，不是成績）

- 5 人中至少 4 人不用工程師逐步引導可操作合成示範；至少 4 人能正確說明備份檢查有限。
- 若真實匯出不支援，應記錄為 `UNSUPPORTED`，不得假裝成功。
- 若 5 人中至少 3 人在獨立下一次需求時願意再使用，可考慮擴展；否則先改善入門流程或往既有開源專案貢獻。

## 安全與限制

測試只使用測試者在自己電腦上的資料；公開紀錄只用固定代碼與去識別統計，且不得包含識別性少數群體特徵、帳號資訊、實際附件名稱或個人聊天。R4 未實際招募測試者，外部驗收狀態仍 `PENDING_HUMAN_EVIDENCE`。
