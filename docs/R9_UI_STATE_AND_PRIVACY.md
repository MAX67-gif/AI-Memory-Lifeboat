# R9 State-Safe Offline｜問題、驗證與回滾契約

**版本：** v0.9.0（日期：2026-11-06）｜僅在正式 GitHub PR、main CI 與 Release 全部成功後可稱已發布。

## 目的與差異

既有 R8 可以在畫面隱藏時，保留前一次的聊天標題／訊息／比較清單等 DOM 內容；一次附件重驗失敗也可能讓前一次成功/失敗狀態進入後續健康指引。R9 不新增新的 AI 供應商或雲端 API，而是確保使用者看到及下載的狀態不會過期。

## 行為規格

- 清除或選擇新的來源：立即清掉舊的列表、細節、比對清單、統計、提示與健康卡，重設回饋欄位。新來源失敗時不得顯示前份結果。
- 比較另一份較早來源：在解析期間撤銷原本的比較結果與先前由比較產生的健康指引；失敗時維持無比較狀態。
- 附件有限 CRC32 重驗：新檢查開始就撤銷前次報告；失敗不可產出上次的成功狀態；清除或更換來源使尚未完成的非同步結果作廢。
- 來源的原始 ZIP／JSON、先前下載的 HTML 與瀏覽器記憶體都不會被本工具安全抹除，保留原始匯出是使用者責任。

## 驗證

- `node --test tests/test_r9_state.js`：使用應用程式真實事件處理器與模擬 DOM 節點，包含原先 R8 失敗的紅燈反例。
- `npm run check`：跑全部既有與新增 Node 測試、檢查 CSP/單檔來源同源與 Manifest。
- 真 Chromium（隔離合成頁面）：桌面和手機操作、取消、清除、過期資料與出站請求。測試僅使用原創合成資料。
- 本次變更若造成歷史 Schema／CRC 限額或 R8 Release 標籤改變，拒絕發布。若正式 CI 失敗，不得用修改既有 tag 或放寬測試救援。

## 已知限制

真實大型官方匯出的全面相容性、實體記憶體安全抹除、下載檔自動刪除、其他 AI 平台匯入、真人獨立採用與 Codex for Open Source 入選都不在本輪聲明範圍。
