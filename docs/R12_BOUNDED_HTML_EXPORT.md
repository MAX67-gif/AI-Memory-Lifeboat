# R12｜單篇對話 HTML 輸出上限與失敗防呆

**範圍：**現有 `core.exportConversationHtml` 使用的單篇目前分支、含原文 HTML 匯出。**不變更** `aml.audit.v1`、R5 Pilot v1/v2、ZIP 來源及附件 CRC32 契約。

## A：問題與替代方案

- 選擇方案：對最終 **UTF-8 HTML 位元組**總量（包括 HTML 特殊字元轉義後增加的長度）設 16 MiB 上限，超過就拒絕產出。這是保守的可重現上限，不是經真人研究優化出來的產品門檻。
- 未選：靜默只匯出前 N 則，會讓使用者誤以為取得完整對話。
- 未選：直接允許任意大小輸出，可能阻塞使用者瀏覽器。
- 未選：自動上傳伺服器處理，與本機保護承諾衝突。

## B：已實作行為

1. 使用者仍需在本機明確確認含原文匯出。
2. 核心依 HTML 轉義後的**真正 UTF-8 bytes**累加；超出 16 MiB → `HTML_EXPORT_TOO_LARGE`，不建出／下載任何部分 HTML。
3. UI 攔截超限與其他未預期例外，顯示固定、安全的錯誤訊息，**不插入原文、檔名或任意 exception**。
4. 原始官方 ZIP 不動；內容無關的 Audit／Health JSON／TXT 仍照舊。
5. R10 下載確認與來源切換撤銷狀態保留。

## 證據與限制

先設計三個會讓 R11 失敗的合成回歸案例（超額長文、HTML Entity 展開、確認視窗後拒絕下載），再在 R12 修復；實際 CI 須核對 GitHub exact PR SHA、main SHA 及新 Release 附件 SHA／CRC。

既有 parser 對單則文字有 `MAX_TEXT` 截長上限。本輪**沒有宣稱修復所有大對話可能被預覽截長的情況**；下一輪應獨立研究「文字截長量及顯示提醒」，避免任何資料遺漏被誤作完整匯出。大小限制用於保護瀏覽器，不是對資料完整性作保證。

OpenAI Codex for Open Source 申請屬私人紀錄，公開資料僅標示核准未經證實；不以申請、補助或使用人數作本輪測試成果。真人試用依維護規劃延期。
