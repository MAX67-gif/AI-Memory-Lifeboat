# R2 雙快照比對｜差異不等於刪除或完整備份證明

版本：應用 v0.2.0；比對摘要 schema `aml.snapshot-diff.v1`。

## 使用流程

1. 從 ChatGPT 官方下載兩次匯出，確認兩份資料確實來自您自己的同一帳戶。
2. 先載入**比較新**的官方 JSON/ZIP，完成單份備份體檢。
3. 選用「較早的備份」上傳舊 JSON/ZIP；工具只在目前瀏覽器內比對。
4. 查看「新版新增、未見、目前分支不同、無法確定」等狀態。摘要 JSON 僅有計數、固定狀態碼和警告，不含對話名稱、ID、訊息內容或檔案路徑。
5. 保留兩份原始官方 ZIP。下載的差異摘要**不是可還原檔**。

可使用原創假資料 `examples/sample-newer.json`（先匯入）與 `examples/sample-older.json`（後匯入）練習。

## 判斷邊界

- `ONLY_IN_NEW_EXPORT`：只在新版匯出出現，不保證帳戶最初沒有此對話。
- `NOT_IN_NEW_EXPORT`：新版**匯出沒有該識別碼**；不表示帳戶已刪除。匯出可能不完整、帳戶可能不同。
- `CURRENT_VIEW_CHANGED`：目前可讀分支文字／角色／時間、節點或附件觀察數不同；**不代表已找出所有內容變更**。
- `METADATA_ONLY_CHANGED`：目前分支檢查相同，但標題或記錄的時間不同。
- `NO_DETECTED_CURRENT_VIEW_CHANGE`：**僅表示本版檢查範圍未見差異**；不包含所有非目前分支、原附件位元組與未匯出資料。
- `INCONCLUSIVE_PATH`：至少一份的 `current_node` 父鏈不完整，不能冒充相同或不同。
- `INCONCLUSIVE_ID`：缺少明確對話 ID 或 ID 重複，不作跨快照配對。

選擇先後順序由使用者指定，工具**不驗證帳戶是否相同、不驗證匯出時間先後**。有內容相同的兩份檔案也不能被宣稱為完整備份。

## 安全與效能

所有檔案仍在使用者目前的瀏覽器記憶體中解析。沒有伺服器 API、遙測、外部字典或遠端 AI；不儲存原始檔至 localStorage/IndexedDB。清除按鈕會撤銷目前畫面保留的資料參照，但不能保證瀏覽器記憶體已經過安全抹除。檔案大小仍受 v0.1 上限限制；同時載入兩份大型匯出會增加記憶體使用，無法保證所有裝置都可處理。

若其中任一檔案不可解析，比對停止；仍可以繼續閱讀已成功載入的最新版。ZIP 的非目標項目僅讀取中央目錄中的檔名等資訊，不開啟附件。
